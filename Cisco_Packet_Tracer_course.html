Background / Scenario

A new switch, Office-SW2, is being added to the network. Before placing a networking device into a network, the device must be configured and tested. Many types of networking devices, such as switches and routers, may not be preconfigured with enough information to make them accessible through an Ethernet or wireless connection. It may be necessary to load an initial configuration using another method. A console connection and a terminal emulation application provide a convenient way to access the device without having to be on an active network.

Part 3: Save the Updated Configuration to the Device

In this part, I will save the configuration changes to permanent memory on the device. If the configuration changes are not saved, they will be lost if the device loses power or is intentionally rebooted. When a Cisco IOS devices starts, it reads the configuration file that is permanent memory and loads it into the running configuration in RAM. Configuration changes are only made to the running configuration. The changes must be saved so that they will become available to a device on startup.

I am going to use the enable command to enter Privileged EXEC mode on the switch again.

I used the copy running-config startup-config command to save the current configuration running on the device to the startup configuration so it starts when I turn the device on.



To verify that the configuration changes were saved properly, I will reload the device using the ‘reload’ command. Reloading the router will reboot the IOS software and IOS will load the saved configuration file. If the new configuration was made and saved in permanent memory, the device will prompt me for a password to access the device console.

Packet Tracer Tutored Activity - Troubleshoot a Wireless Connection

Objectives

Identify faults in a wireless network.
Correct misconfigured devices in a wireless network.

Background / Scenario

At a local library, the librarian learns that a patron is unable to access the internet on one of the laptops. All the computers are configured with DHCP IP addressing except for the wireless user on Laptop1, who is complaining that www.cisco.pka cannot be reached. Identify and resolve the issue, then verify the resolution.
Before I can fix the problem, I need to understand which devices are affected. This helps determine whether a single computer has a fault, or if the entire network or parts of the network are affected.









The problem lies in the IP configuration of the laptop that cannot connect to the internet. Here's a comparison of the differences between the configurations of the non-working and working laptops





Key Differences:


IPv4 Address:

Non-working Laptop: 169.254.34.68
Working Laptop: 192.168.1.2

Subnet Mask:

Non-working Laptop: 255.255.0.0
Working Laptop: 255.255.255.0

Default Gateway:

Non-working Laptop: 0.0.0.0
Working Laptop: 192.168.1.1

Here is what I found when I looked into why there is a difference between the IPv4 Addresses. The IPv4 address 169.254.34.68 on the non-working laptop indicates that it has an APIPA (Automatic Private IP Addressing) address. This typically happens when the device cannot obtain an IP address from the DHCP server. And the cause is probably the default gateway on the non-working laptop is not set correctly (0.0.0.0), meaning it cannot route traffic to the internet.

I tried restarting the DHCP client.



This forces the laptop to request a new IP address from the DHCP server. But it didn't work.

I just needed to refresh it from the PC wireless app.



I will try using the default gateway's IP address in the web browser to access the wireless router and view the security information for the password.









Laptop1 is now connected to the internet and running.
